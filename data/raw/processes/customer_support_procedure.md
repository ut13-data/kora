# Customer Support Procedures

## Purpose
Define how customer-reported tickets are triaged, worked, and resolved.

## Ticket Lifecycle

1. **Intake** — Ticket created via customer portal, email, or (Priority tier only) phone.
2. **Triage (L1)** — L1 Support Engineer classifies ticket type (question, known issue,
   potential bug) and priority (P1–P4, see PROC-SUP-002).
3. **First response** — Per SLA tier (see DOC-PROD-IMPLSUP).
4. **Resolution or escalation** — L1 resolves known issues directly. Unresolved or
   complex issues escalate to L2, then L3 if a product defect is suspected.
5. **Bug confirmation path** — If L3 confirms a product defect, PROC-ENG-002 is
   triggered.
6. **Closure** — Ticket closed with resolution notes; customer receives a closure
   summary.

## Terminology Note
This document uses "bug" for confirmed product defects, consistent with customer-facing
language. Engineering's internal documentation (PROC-ENG-001, PROC-ENG-002) uses
"defect" — same concept, see glossary.md TN-008.
